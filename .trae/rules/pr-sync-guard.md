# 开工前协作同步检查（本项目固定流程）

> 📐 本文件是**薄指针**，不是规范正文。
> 本项目协作规范的**唯一事实来源 = 仓库根目录 `AGENTS.md`** —— 请**先完整读它**（尤其 §4 本节、§3 硬约束）。
> ⛔ DO NOT COPY THE BODY OF AGENTS.md HERE. 正文复制成多份后必然漂移，届时无人知道哪个版本算数。
> 本文件只保留**最小可执行摘要**，用于兜底。

**这不是可选建议，是本项目协作的第一步。在阅读代码、修改任何文件之前，先完成下面三步。**

## 最小可执行摘要

1. **拉** —— 开工第一步永远是 `git pull origin dev`，`git status` 确认干净后才开工。
2. **看** —— 动手前对目标文件跑 `git log --oneline -5 -- <文件>`；合作者刚改过且改动可能重叠 → 先向用户说明再动；大改动先拉个人分支（`cc/功能名` / `myh/功能名`）。
3. **解** —— push 被拒 = 合作者先推了 ⇒ `git pull origin dev` 逐块解决冲突（合并两边 / 取正确版 / 拿不准问用户），解完跑 `npx tsc --noEmit` 再推。

> ⛔ DO NOT FORCE PUSH —— 会抹掉合作者已推送的提交，不可恢复。
> ⛔ DO NOT DISCARD —— 禁止 `git checkout -- .` / `git reset --hard` 清工作区"消冲突"，会连本地未提交工作一起丢。
> ⛔ DO NOT SKIP 历史教训：跳过拉取 = 基于旧代码开发 = 冲突返工（2026-09、2026-10 均实际发生）。

## 边界

- 不越权：**不直接推 `main`**；不向展示仓库 `quickclass-release` 提交。
- 冲突拿不准时**停下问用户**，禁止删掉对方改动来"让冲突消失"。
